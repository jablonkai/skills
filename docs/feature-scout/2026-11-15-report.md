## 1. Product profile

| | |
|---|---|
| **What it is** | A personal, public catalog of Agent Skills (`SKILL.md` format) for AI coding agents, mostly app-automation skills. |
| **Target users** | First the author; second, Claude Code (and compatible agent) users who want an agent to drive a desktop app or CLI: creative, document, video, CAD and macOS tools. |
| **Core use cases** | Automate a GUI app or CLI headless with read-back verification; run GitHub issue/PR workflows; audit, test, document and refactor code; look up ultrarunning data. |
| **Platforms** | Claude Code and other Agent Skills-compatible agents; many skills are macOS-only (Apple apps, AppleScript/JXA). |
| **Monetization** | None. GPL-3.0-only, 4 GitHub stars. |

**Current features**

- 81 skill directories, each with one `SKILL.md`; 77 ship `references/`, 70 ship `scripts/` — `skills/`
- Strict frontmatter contract incl. per-skill SemVer, `compatibility` (exact app versions) and `risk` on all 81 skills — `AGENTS.md`, `.github/scripts/validate.sh`
- Generated catalog grouped into themes — `.github/scripts/generate-catalog.sh:29` (`CATALOG_SECTIONS`)
- CI: validation and static lint of shipped scripts — `.github/workflows/validate.yml`
- Install docs for the `skills` CLI and `gh skill` — `README.md:134`

**Obvious gaps and rough edges**

- No git tags or releases, although `README.md` tells users to pin with `--pin <tag-or-sha>` — only a SHA can work today.
- No Claude Code plugin marketplace manifest (no `.claude-plugin/`); install is per skill or all 81.
- No committed evals in any skill; `*-workspace/` is gitignored, so triggering quality is not evidenced anywhere.
- `risk` is recorded for every skill but not shown in the README catalog.
- No `SECURITY.md`, `CONTRIBUTING.md` or issue templates.
- 45 open issues, all of them "Add <app> skill" requests: the backlog is pure breadth.
- CI cannot execute the app bridges (stated in `AGENTS.md`), so a skill breaking after an app update is found by hand; recent history is manual "verify against x.y.z" commits.

### 1. Show `risk` (and platform) in the generated catalog

- **Problem:** Trust is the loudest complaint in this ecosystem, and this repo's own trust signal is invisible to anyone browsing the README.
- **Proposed solution:** Have the generator render a compact risk marker (and a macOS-only marker derived from `compatibility`) per catalog line, with a legend linking to the risk scale.
- **Evidence:** the most-discussed open issue on the official repo is about trust boundaries ([anthropics#492](https://github.com/anthropics/skills/issues/492)); skills.sh shows three audit verdicts on every skill page ([detail page](https://www.skills.sh/vercel-labs/skills/find-skills)) while stating it "cannot guarantee the quality or security of every skill" ([docs](https://www.skills.sh/docs)); signature verification is still an RFC ([vercel-labs#617](https://github.com/vercel-labs/skills/issues/617)).
- **Value:** 4 — cheap, and it turns existing metadata into a differentiator.
- **Effort:** S — one more field read in the generator; the data is already complete.
- **Strategic fit:** high.
- **Affected code:** `.github/scripts/generate-catalog.sh`, `.github/scripts/catalog-lib.sh`, `README.md` and `AGENTS.md` (generated sections).
- **Technical risks:** `summary` is spliced as plain text; the platform marker needs a reliable rule, or a new frontmatter field, which the validator's allow-list would have to accept.

### 2. Plugin marketplace manifest with theme bundles

- **Problem:** A user who wants "the video skills" must name each one or install all 81.
- **Proposed solution:** Generate `.claude-plugin/marketplace.json` from `category`/`CATALOG_SECTIONS`, one plugin per theme, and fail CI on drift like the catalog does.
- **Evidence:** role-based plugin bundles with `/plugin install <name>@…` ([alirezarezvani README](https://github.com/alirezarezvani/claude-skills)); official repo ships plugin sets ([anthropics#189](https://github.com/anthropics/skills/issues/189)); skills.sh "Packs" bundle skills into one install command ([docs](https://www.skills.sh/docs)).
- **Value:** 4. **Effort:** M — the grouping exists; the manifest schema needs checking against current plugin docs.
- **Strategic fit:** high.
- **Affected code:** `.github/scripts/generate-catalog.sh`, `.github/scripts/validate.sh`, new `.claude-plugin/marketplace.json`, `README.md` install section.
- **Technical risks:** overlapping bundles install duplicates, exactly the bug in [anthropics#189](https://github.com/anthropics/skills/issues/189); keep bundles disjoint.

### 3. Tag releases and generate release notes

- **Problem:** `--pin <tag>` is documented but there are zero tags; nobody can see what changed.
- **Proposed solution:** A release workflow that tags on a schedule or on demand and lists skills whose `metadata.version` changed since the last tag.
- **Evidence:** [superpowers releases](https://github.com/obra/superpowers/releases) (v7.0.2, 2026-11-03), [alirezarezvani releases](https://github.com/alirezarezvani/claude-skills/releases) with descriptive titles.
- **Value:** 3. **Effort:** S — the validator already diffs versions against the base branch.
- **Affected code:** new `.github/workflows/release.yml`, reuse of the version-diff logic in `.github/scripts/validate.sh`.
- **Technical risks:** low; needs `contents: write` permission in the workflow.

### 4. Commit trigger evals and publish a verified list

- **Problem:** Nothing shows that a skill's description actually makes an agent load it.
- **Proposed solution:** Keep a small `evals/` trigger set per skill in the repo, and generate a "verified" marker in the catalog from the last recorded run. Start with the ten most-used skills.
- **Evidence:** "Each of these loaded on every plain-language test prompt" with a `VERIFIED.md` ([alirezarezvani README](https://github.com/alirezarezvani/claude-skills)); the official trigger-eval script failing for users shows the tooling is fragile ([anthropics#556](https://github.com/anthropics/skills/issues/556)).
- **Value:** 4. **Effort:** L across 81 skills, M for a pilot.
- **Affected code:** `skills/*/evals/`, `.gitignore`, `.github/scripts/validate.sh` (allow the directory), `generate-catalog.sh`.
- **Technical risks:** results depend on model and installed-skill set, so a recorded "verified" goes stale; record model and date. Whether `evals/` installs to end users needs checking.

### 5. Local compatibility-drift check

- **Problem:** Skills pin exact app versions, but a broken skill is noticed only when it fails in use.
- **Proposed solution:** A local script that parses each `compatibility` string, reads the installed app/CLI version, and prints the skills that are behind. CI cannot do this, a maintainer's machine can.
- **Evidence:** mostly internal (recurring "verify against" commits). Externally, staleness is a top complaint about the directory itself ([vercel-labs#2192](https://github.com/vercel-labs/skills/issues/2192), [#780](https://github.com/vercel-labs/skills/issues/780)); no competitor was seen doing version-drift checks **(unverified absence)**.
- **Value:** 4 for the maintainer. **Effort:** M — `compatibility` is free text; a version probe per app is needed.
- **Affected code:** new `.github/scripts/check-compat.sh`, possibly a per-skill version-probe convention.
- **Technical risks:** free-text parsing is brittle; a structured field would need a validator change.

### 6. "Start here" section and skills.sh badge

- **Problem:** 81 entries in theme lists give a newcomer no first step and no popularity signal.
- **Proposed solution:** A short hand-written "start with these" block above the generated catalog, plus the install-count badge.
- **Evidence:** "Pick your role" and "Start with these" ([alirezarezvani README](https://github.com/alirezarezvani/claude-skills)); badge snippet `skills.sh/b/owner/repo` ([skills.sh docs](https://www.skills.sh/docs)).
- **Value:** 3. **Effort:** S. **Affected code:** `README.md` (outside the generated markers).
- **Technical risks:** none; whether this repo is indexed on skills.sh was not checked.

### 7. `SECURITY.md`, issue templates, per-skill issue titles

- **Problem:** No channel for reporting an unsafe skill, and bug reports have no skill or app-version field.
- **Proposed solution:** `SECURITY.md`; a bug template asking for skill name, skill version, app version; `[skill-name]` title convention.
- **Evidence:** bracketed per-extension issue titles ([raycast issues](https://github.com/raycast/extensions/issues?q=is%3Aissue+is%3Aopen+sort%3Acomments-desc)); security reports routed to a dedicated address ([skills.sh docs](https://www.skills.sh/docs)).
- **Value:** 2 at 4 stars; rises with adoption. **Effort:** S.
- **Affected code:** `SECURITY.md`, `.github/ISSUE_TEMPLATE/`.

### 8. Scaffold script for new skills

- **Problem:** 45 queued "add skill" issues, each needing eight required frontmatter fields set by hand.
- **Proposed solution:** `new-skill.sh <name> <category>` that writes a valid skeleton and runs the generator and validator.
- **Evidence:** `npx skills init [name]` ([vercel-labs/skills README](https://github.com/vercel-labs/skills)).
- **Value:** 3. **Effort:** S. **Affected code:** new `.github/scripts/new-skill.sh`, `AGENTS.md` ("Adding a new skill").
