# Symbolication and deobfuscation

A release-build trace is unreadable until it is mapped back to source symbols. Do this **before**
analysis — conclusions drawn from `a.b.c(Unknown Source)` or a bare hex address are guesses.

## Recognising an unreadable trace

| Symptom | Meaning |
|---|---|
| `a.a.a.b(SourceFile:1)`, one/two-letter names | R8/ProGuard obfuscated (Android) |
| `at <unknown> 0x104a2b1c8` or raw addresses only | Unsymbolicated native frames (Apple, NDK, C++) |
| `#0 0x00007f... in ?? ()` | No debug symbols in the binary (C/C++) |
| `dart:...` frames but numeric app frames | Obfuscated Flutter release build |
| `<optimized out>`, missing inlined frames | Release optimization; symbols exist but frames were folded |
| `Unknown Source` / no line numbers | Compiled without debug info, or line-number table stripped |

Missing artifacts is a legitimate answer. If the mapping file or dSYM for that exact build is
gone, say so — a mapping file from a *different* build produces confidently wrong names.

## Android — R8 / ProGuard

The mapping file is produced per build variant and is **build-specific**:

```
app/build/outputs/mapping/<variant>/mapping.txt
```

Retrace with the bundled tool (R8 ships with the Android Gradle plugin):

```bash
# R8 (preferred, AGP 7+)
java -jar "$ANDROID_HOME"/cmdline-tools/latest/lib/r8.jar retrace \
  app/build/outputs/mapping/release/mapping.txt stacktrace.txt

# ProGuard-era projects
retrace.sh -verbose mapping.txt stacktrace.txt
```

Notes:

- Play Console and Crashlytics deobfuscate automatically when the mapping file was uploaded for
  that build — check there before hunting for local artifacts.
- `mapping.txt` is regenerated by every release build. If it was not archived, the trace cannot
  be recovered for that build; ship the fix for archiving it (`android.buildTypes.release` +
  CI artifact upload) as a follow-up note.
- Line numbers survive obfuscation only if `-keepattributes SourceFile,LineNumberTable` (plus
  `-renamesourcefileattribute`) is configured. Without it, expect method names but no lines.

## Android native (NDK / C++)

```bash
# Symbolicate a native crash from logcat using unstripped .so files
adb logcat | ndk-stack -sym app/build/intermediates/merged_native_libs/release/out/lib/arm64-v8a

# From a saved log
ndk-stack -sym <path-to-unstripped-libs> -dump crash.log
```

Requires the **unstripped** libraries from the same build. `addr2line` is the manual fallback —
see [rust-cpp.md](rust-cpp.md).

## Apple — iOS / macOS

Crash reports (`.ips` on modern OS versions, `.crash` historically) need the dSYM bundle matching
the build's UUID.

```bash
# UUID of the crashed binary appears in the report's "Binary Images" section
grep -A 5 "Binary Images" report.ips

# UUID of a local dSYM — these must match exactly
dwarfdump --uuid MyApp.app.dSYM

# Symbolicate a single address
atos -o MyApp.app.dSYM/Contents/Resources/DWARF/MyApp -arch arm64 -l <load-address> <address>

# Whole report (path varies by Xcode version)
/Applications/Xcode.app/Contents/SharedFrameworks/DVTFoundation.framework/Versions/A/Resources/symbolicatecrash \
  report.ips MyApp.app.dSYM > symbolicated.txt
```

Notes:

- Xcode symbolicates automatically when the archive is still in the Organizer — check there first.
- With Bitcode-era or App Store-recompiled builds, download the dSYMs from App Store Connect
  rather than using the local ones.
- Swift symbols come out mangled (`$s5MyApp...`); demangle with `swift demangle` or
  `xcrun swift-demangle`.

## Flutter / Dart

Obfuscated release builds need the symbol files written by `--split-debug-info`:

```bash
flutter build apk --obfuscate --split-debug-info=build/symbols

flutter symbolize -i crash.txt -d build/symbols/app.android-arm64.symbols
```

`flutter symbolize` requires the symbol file from the exact build that crashed. Web (dart2js)
traces need the source map instead; ship `--source-maps` and map with a JS source-map tool.

## Rust

```bash
RUST_BACKTRACE=1 ./target/release/app        # symbol names
RUST_BACKTRACE=full ./target/release/app     # + all frames, including std internals
```

Release binaries need `debug = true` (or `debug = "line-tables-only"`) in the `[profile.release]`
section of `Cargo.toml` for line numbers. If the binary was stripped, symbolicate from a separate
debug file with `addr2line -e app.debug <addr>`.

## C / C++

```bash
addr2line -e ./app -f -C -i 0x4011a6     # -C demangle, -i show inlined frames
gdb ./app core                            # then: bt full
lldb ./app -c core                        # then: bt all
eu-unstrip / objcopy --only-keep-debug     # when debug info was split into a separate file
```

Requires the binary built with `-g` (or a matching separate debug file) and the same build id —
verify with `readelf -n ./app | grep -i 'build id'`.

## Handling privacy

Crash reports carry device identifiers, filesystem paths with usernames, and internal symbol
names. Keep them local: do not upload them to third-party services or paste them into external
tools during analysis.
